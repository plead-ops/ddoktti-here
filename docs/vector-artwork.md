# 원본 기반 SVG 캐릭터

원본 비트맵의 얼굴, 안경, 의상과 포즈를 유지하며 SVG 경로로 변환한다. 새 캐릭터 리그로 대체하지 않는다.

## 보정 기준

- `assets/concepts/pet-frame-guides.json`: 검토한 원본 추출 좌표와 얼굴 측정값. 창 이동 시트는 열마다 실제 행 사이의 빈 구간으로 분리한다. 균등 행 분할이나 잘린 부분 삭제로 처리하지 않는다.
- 어두운 원본 픽셀은 외곽선/정장 팔레트와의 거리로 분류하되, 원본 정장에 연결된 천 영역은 기존 정장색으로 평탄화한다. 정장의 음영까지 검은 선으로 바꾸면 드래그 프레임이 위장무늬처럼 깨지므로 머리·안경의 외곽선 정리와 분리한다. 외곽선의 회색·남색 얼룩을 방지하며 최종 외곽선은 `#081724`로 통일한다.
- 모든 프레임은 동일한 11색 팔레트 사용. 캐릭터의 초록, 안경 파랑, 정장과 외곽선의 색을 통일하며 알림 소품의 구분 색은 유지한다.
- 안경 렌즈의 폭·간격을 측정해 공통 크기로 정렬한다. 얼굴 중심과 발 기준선을 고정하며, 캐릭터 전체에 가로·세로 동일한 배율을 적용한다. 몸통·하체를 따로 압축하거나 늘리지 않는다. 원본 자체의 포즈별 해부학적 차이는 이 정렬 과정에서 변형하지 않는다.
- 원본부터 안테나가 없는 창 이동 4·13·15번 프레임에는 같은 원본 시트의 안테나 경로를 가져와 얼굴과 팔 뒤에 배치한다.
- 반투명 배경 잔여 픽셀은 알파 128 기준으로 제외한다. 벡터 근사와 색상·비율 보정 때문에 원본과 픽셀 단위로 동일하지는 않다.

## 파일과 재생

- 보존 원본: `assets/concepts/raster-before-svg/` (앱 번들 제외)
- 독립형 SVG: `apps/desktop/public/sprites/vector/frames/` (129개)
- 재현 가능한 개별 보정: `scripts/pet-art-repairs.py`. 감정 표현 20프레임의 누락된 밑단. 착지·아야·졸기는 아래 새 원화에서 추적하며 수작업 몸통/입 덧칠을 사용하지 않는다. 손·다리에 가려진 밑단을 관통해 그리지 않는다.
- 런타임 경로: `apps/desktop/src/pet-vector-paths.json`
- 정렬·클릭 영역: `apps/desktop/src/pet-vector-frames.json`
- 공통 팔레트: `apps/desktop/src/pet-palette.json`
- 실제 앱 재생: `apps/desktop/src-tauri/src/native_pet/`
- 브라우저 미리보기 재생: `apps/desktop/src/pet-vector.ts`
- 줄을 잡는 손 좌표: `assets/concepts/pet-climb-hand-guides.json` → `apps/desktop/src/pet-climb-hands.json`
- 기본 서 있는 자세: `emotions-v2`의 18번 프레임을 재사용한다. 이전 `edge` 3번의 긴 몸통·다리 대신 기존 휴식 자세를 선택하며, 세로 압축이나 부위별 변형은 하지 않는다. 네이티브와 웹 미리보기의 선택을 함께 유지한다.
- 첫 시작 화면: 보정된 손 흔들기 프레임의 `welcome.svg`
- 아이콘: `assets/icons/app-icon.svg`; OS에 필요한 PNG/ICO/ICNS를 여기서 생성

브라우저 미리보기 렌더러는 외부 `<image>`를 교체하지 않는다. 각 SVG 안에 프레임별 경로 그룹을 한 번 생성해 보관하고, 표시 여부와 위치만 갱신한다. 재생 중 파일 로딩이나 이미지 디코딩을 기다리지 않으며 기존 DOM을 매번 삭제하지 않는다. 숨긴 프레임은 클릭 영역에 포함되지 않는다.

실제 앱은 같은 경로를 resvg로 래스터화하여 네이티브 투명 창에 직접 그린다. 구조와 검증 범위는 [네이티브 렌더링](native-rendering.md)을 참고한다.

## 다시 생성

일반 빌드는 Python을 요구하지 않는다. 아트 원본이나 보정 기준 변경 시에만 Python 3.13 venv에서 실행한다. VTracer 0.6.11은 이 작업 환경의 Python 3.14에서 매개변수 전달 중 충돌하여 3.13을 사용한다.

```sh
uv venv --python 3.13 /private/tmp/ddoktti-art-venv
uv pip install --python /private/tmp/ddoktti-art-venv/bin/python -r scripts/vector-requirements.txt
/private/tmp/ddoktti-art-venv/bin/python scripts/trace-pet-svg.py
/private/tmp/ddoktti-art-venv/bin/python scripts/check-art-cleanup.py
pnpm svg
pnpm icons
```

`pnpm svg`는 정적 SVG 미리보기를 만들고 `pnpm icons`는 같은 미리보기와 네이티브 아이콘을 만든다. 시스템 Python에 패키지를 설치하지 않는다.

검토 페이지: `/motions.html`, `/surfaces.html`, `/ui-preview.html`, `/playground.html`.

## 반드시 지킬 제작 규칙

이 문서는 이후 캐릭터 제작·수정 때 적용할 기준이다. 현재 사용자가 승인한 원본 인상을 우선한다.

### 캐릭터의 정체성

- 초록 얼굴, 큰 파란 안경, 파란 끝의 안테나, 짙은 정장, 파란 넥타이와 작은 금색 배지를 유지한다.
- 얼굴·눈·안경의 모양, 짧은 팔다리와 전체 실루엣을 참조 이미지에 맞춘다. SVG 변환을 이유로 별개의 캐릭터를 다시 디자인하지 않는다.
- 신규 동작도 승인된 기존 프레임을 함께 참조한다. 텍스트 설명만으로 캐릭터를 새로 생성하지 않는다.
- 원본에서 가려진 부위와 실제로 누락된 부위를 구분한다. 손을 들었다는 이유로 안테나를 삭제하지 않는다.

### 원본과 생성물 관리

- 보존 원본을 덮어쓰지 않는다. 생성 프롬프트, 참조 파일, 시트의 행·열 배치, 동작 순서와 채택 프레임을 함께 기록한다.
- 수정의 기준은 생성 스크립트·가이드·팔레트다. 결과 SVG만 손으로 바꾸면 다음 생성 시 사라지므로 재현 가능한 보정으로 남긴다.
- SVG는 실제 벡터 경로여야 한다. SVG 안에 PNG를 넣는 방식으로 형식만 바꾸지 않는다.
- 앱에는 동작을 고르는 메뉴를 추가하지 않는다. 동작 선택·타임라인은 개발용 미리보기에서만 제공한다.

### 프레임과 투명 배경

- 생성 시트의 행 높이가 일정하다고 가정하지 않는다. 열별 실제 캐릭터 범위를 확인하고 손끝·발끝·안테나까지 포함한다.
- 다른 행의 발이나 안테나가 섞였으면 원본 추출 좌표를 먼저 수정한다. 큰 조각을 삭제해 잘림을 숨기지 않는다.
- 투명 배경의 낮은 알파 픽셀은 벡터 변환 후 불투명한 검은 점으로 바뀔 수 있다. 알파 임계값과 잡티 제거는 작은 배지·손가락·눈동자를 지우지 않는지 확대 검토한다.
- 별도 모션선·표정 효과는 잡티와 구분한다. 밝은 배경과 어두운 배경에서 모두 확인한다.

### 비율과 위치 — 금지 사항 포함

- 전체 포즈의 가로·세로에 동일한 배율을 적용한다. 얼굴 크기 측정과 발 기준선 정렬을 통해 장면 간 크기를 맞춘다.
- **몸통이나 하체의 높이에 상한을 두거나 세로로 압축하지 않는다.** 이전 56단위 하체 상한은 몸이 눌려 보이는 문제로 폐기했다. 다시 도입하지 않는다.
- 머리, 몸통, 다리를 서로 다른 배율로 변형해 크기를 맞추지 않는다.
- 포즈별 원근·웅크림·무릎 굽힘은 보존한다. 실제로 잘못 그려진 다리는 해당 부위의 원본 형태를 개별 수정한 후 재검토한다.
- 걷기·달리기의 보폭·프레임 시간은 `pet-gaits.json`을 함께 조정한다. 실제 이동 거리에서 프레임을 진행하고, 그림 재생과 이동에 서로 다른 고정 속도를 주지 않는다.
- 걷기·달리기는 발 기준선을 유지한다. 별도 상하 바운스를 임의로 추가하지 않는다. 점프·낙하 같은 의도된 이동은 그림 자체의 왜곡 대신 위치로 처리한다.
- 현재 정렬 기준은 400×260 좌표계, 얼굴 기준 중심 x=200, 발 y=250, 안경 측정 폭 90이다. 안경 측정 폭은 눈을 감거나 소품을 들었을 때 자동 검출이 틀릴 수 있으므로 가이드를 눈으로 검토한다.

### 동작과 렌더링

- 동작의 순서, 프레임 간격, 실제 위치 이동을 함께 확인한다. 정지 그림만 좋다고 애니메이션을 완료 처리하지 않는다.
- 달리기는 양발의 지지·회수 순서가 읽혀야 한다. 한쪽 발을 끌거나 발 길이가 튀는 장면은 비교 검토한다.
- 등반은 손을 뻗기 → 줄/모서리를 잡기 → 당길 때 상승 → 다시 잡기의 타이밍을 맞춘다. 정상에서는 몸을 올리고 줄을 회수한다. 원본의 무릎 동작을 활용하며 팔다리를 찌그러뜨리지 않는다.
- 등반 줄의 고정점은 실제 창 모서리를 따른다. 창 이동·크기 변경·최소화·닫힘, 반대 방향 등반, 모니터 배율 변경을 확인한다.
- 캐릭터와 줄이 주변 클릭을 막지 않도록 실제 캐릭터 영역과 팝업만 입력 대상으로 삼는다. 줄은 장식 요소이며 클릭 영역으로 포함하지 않는다.
- 브라우저 미리보기에서는 SVG 경로 그룹을 재사용한다. 매 프레임 `<image>` 교체나 전체 DOM 삭제를 하지 않는다.
- 네이티브 전환에서도 같은 SVG 원본·균등 배율을 사용한다. 화면 배율에 맞춰 렌더링하고 캐시로 프레임 재로딩을 피한다. 네이티브 전환 자체가 잘못된 그림이나 동작 순서를 고쳐주지는 않는다.

### 완료 확인

1. 원본과 결과를 같은 배율로 비교한다. 얼굴뿐 아니라 몸통·다리와 손발 끝을 확인한다.
2. 전체 동작을 밝은 배경·어두운 배경·투명 격자에서 재생한다.
3. 동작 간 전환, 좌우 반전, 0.5× 재생, 동작 줄이기 설정과 정지 프레임을 확인한다.
4. SVG 외부 이미지·내장 비트맵, 뷰포트 밖으로 잘리는 곡선, 색상 이탈, 상하 비대칭 배율이 없는지 검사한다.
5. 실제 앱의 클릭·깨우기·드래그·알림·창 등반을 확인한다. 브라우저 미리보기 통과를 OS 실기기 검증으로 표현하지 않는다.
6. 타입 검사·빌드와 관련 테스트를 실행하고, 확인한 환경과 미검증 환경을 구분해 기록한다.

```sh
pnpm typecheck
pnpm --filter @ddoktti/desktop build
node --test tests/pet-gait.test.mjs tests/pet-vector.test.mjs tests/pet-behaviors.test.mjs tests/pet-layout.test.mjs tests/pet-surfaces.test.mjs
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
```

원본 인상 변경, 다리 압축, 균등 시트 잘라내기, 알파 잡티의 불투명화, 이미지 교체에 따른 깜빡임은 이미 발생했던 회귀 사례다. 새 제작이나 최적화 시 같은 문제가 다시 생기지 않는지 우선 확인한다.


### 정장 얼룩 회귀 방지

2026-10-01 재검토에서 어두운 색상 임계값만 올리면 드래그(`interactions-v2` 4~7) 정장 음영이 검은 조각으로 바뀌는 문제가 확인됐다. `clean_pixels`는 기존 색 분류의 연결된 정장 영역을 보존하고, 안경·안테나의 외곽선은 통일된 검정으로 유지한다. 구조적인 검은 봉제선과 투명 배경은 보존한다. `check-art-cleanup.py`에 해당 구분을 회귀 검사로 남겼다. 걷기·달리기에 이미 있는 밑단 위로 수동 선을 덧그리지 않는다. 특히 `walk-0`의 기존 추가 곡선은 옷 밖으로 나왔으므로 제거했다.

### 세부 선 정리 (2026-10-01 후속)

감정 표현 `emotions-v2` 전체 20프레임은 자세별 밑단을 보정하고 원래 정장 채움 경로로 클리핑한다. 손이나 소품 위를 지나가거나 외곽으로 선이 삐져나오지 않도록 한다. 이후 사용자 피드백으로 수작업 착지 몸통·옷깃과 하품 입 덧칠은 폐기했다. 아래 원화 재생성 방식이 현재 구현이다. 모두 기존 균등 배율과 손발 위치를 유지한다.

### 착지·아야·하품 원화 재생성

사용자가 수작업 SVG 형태와 하품 입 주변의 녹색 띠를 지적하여 imagegen 스킬의 내장 도구로 다시 생성했다. [원화와 프롬프트](../assets/concepts/generated/GENERATION.md)를 보존한다. `landing-hurt-v2.png` 6프레임 중 첫 프레임은 `edge-v2-6`, 나머지는 `hurt-v1` 0~4에 배치한다. `sleep-yawn-v3.png` 4프레임은 `behaviors-v2` 8~11을 대체한다.

`generated/frame-guides.json`에 실제 크기·크롭·흰 렌즈 범위·목선을 기록했다. 원본 알파를 보존하며 벡터화 시 기존 임계값과 팔레트를 적용한다. 기존과 동일하게 흰 렌즈 범위 90, 발 y=250으로 균등 확대·축소한다. `trace-pet-svg.py`가 생성 원화를 직접 추적하므로 별도 수작업 몸통/얼굴 SVG를 합성하지 않는다. 프레임 키와 총 129프레임은 유지한다. 아야 동작은 눈 감은 1·2번만 반복하고 3번 눈 뜨기→4번 진정으로 마친다.

새로운 복잡한 캐릭터 자세는 기존 인상을 참고한 생성 원화를 먼저 만들고 벡터로 추적한다. 기존 머리에 각진 SVG 몸통·팔다리를 조립하거나, 입 주변을 큰 녹색 도형으로 덮어 윤곽을 숨기는 방법은 사용하지 않는다. 단순 옷자락 보정과 새 자세의 제작을 구분한다.
