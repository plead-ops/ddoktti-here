# 네이티브 캐릭터 렌더링

캐릭터는 브라우저를 포함하지 않는 `pet-native` 투명 창에 직접 그린다. 설정·계정 연결·첫 실행 화면과 알림 말풍선·메뉴는 기존 HTML UI를 유지한다. 앱 전체에서 WebView를 제거하는 변경은 아니다.

## 책임과 파일

- `src-tauri/src/native_pet/mod.rs`: 자율 행동, 클릭·깨우기·드래그, 표시 모드, 네이티브 창과 HTML 팝업의 상태 동기화.
- `native_pet/physics.rs`: 창 가림·지지면, 이동·등반·점프·낙하·착지. 좌표는 모니터 작업영역 기준 논리 좌표다.
- `native_pet/art.rs`: 승인된 SVG 경로를 resvg로 화면 배율에 맞게 래스터화하고 줄을 합성한다. 캐릭터의 가로·세로 배율은 같다.
- `native_pet/platform.rs`: macOS의 CALayer/CGImage, Windows의 UpdateLayeredWindow. premultiplied RGBA를 사용하며 Windows 전송 시 BGRA로 변환한다.
- `src/overlay.ts`: 알림·메뉴·반응 말풍선만 처리한다. 캐릭터 아틀라스, requestAnimationFrame, 이동 IPC를 사용하지 않는다.
- `src/pet-surfaces.ts`, `pet-vector.ts`, `pet-rope.ts`: 개발용 브라우저 미리보기. 실제 앱의 이동 엔진은 Rust다.

Rust/JavaScript의 Tauri 및 updater는 2.12 계열로 맞춘다. Tauri의 WebView 없는 WindowBuilder API를 사용하기 위해 `unstable` feature를 활성화한다. 의존성 갱신 때 실제 앱 빌드도 실행해 양쪽 버전의 호환성을 검사한다.

## 보폭과 재생 속도

`src/pet-gaits.json`이 Rust와 미리보기의 공통 기준이다. 400×260 원화 좌표에서 걷기 한 주기(8프레임, 1.04초)의 이동 거리는 88, 달리기 한 주기(4프레임, 0.46초)는 112다. 승인된 짧은 다리의 보폭에 맞춘 조정값으로, 실제 이동 시 미끄러짐을 비교 검토하며 수정한다.

속도는 `원화 보폭 × 캐릭터 크기 / 260 ÷ 한 주기 시간 × 속도 설정`으로 계산한다. 기본 크기 180에서는 걷기 약 59, 달리기 약 169 논리 px/s다. 이동한 실제 수평 거리를 누적해 프레임 진행 시간을 구하므로 멈추거나 경계에 막히면 제자리에서 계속 걷지 않는다. 창 자체의 이동과 드래그 거리는 걸음에 더하지 않는다. 행동 지속 시간은 별도로 관리하며 몸을 상하로 튕기거나 늘리지 않는다.

## 이동과 줄

등반은 0.8초 주기로 손 뻗기 → 당기기 → 다시 잡기를 반복한다. 앞뒤 1/4 구간은 높이를 유지하고 가운데 1/2 구간에 부드럽게 상승한다. 프레임 순서는 1 → 0 → 2 → 3이며 양쪽 방향에서 같은 타이밍을 사용한다. 창 꼭대기에 오르면 줄을 회수한다.

줄은 실제 창 모서리를 고정점으로 사용하고, 손 위치는 `assets/concepts/pet-climb-hand-guides.json`의 원본 좌표에서 변환한다. SVG 재생성 시 `pet-climb-hands.json`도 함께 생성한다. 새 원본으로 바꾸면 손 좌표를 다시 검토한다. 줄은 클릭 영역에 포함하지 않는다.

창이 이동하거나 크기가 바뀌면 고정점과 캐릭터를 함께 이동한다. 창이 닫히거나 가려지면 줄을 놓고 낙하한다. 드래그와 동작 줄이기도 줄을 해제한다. 공중에서 알림이 도착하면 안전하게 착지한 다음 말풍선을 보여준다. 준비 중인 이동 점프는 알림이 오면 취소한다.

## 입력·설정

- 클릭: 간지럽히기. 졸고 있으며 알림이 없으면 놀라서 깨어난다.
- 우클릭: HTML 메뉴. 공중에서는 착지 후 표시한다. 메뉴는 우상단 X로 닫고(별도 닫기 버튼 없음), 타이머가 돌고 있으면 시작 폼 대신 남은 시간·일시정지/이어서·중지를 보여 준다. "30분 동안 알림 끄기"는 항상 보이며, 켜진 동안에는 "알림 다시 켜기 · HH:MM까지 꺼짐"으로 바뀐다.
- 드래그: 포인터가 안테나 끝을 잡는다. 안테나 끝 좌표는 프레임 경로 데이터의 최상단 점(`Art::tip`)으로 구하고, 몸은 그 점을 축으로 하는 감쇠 진자(`swing`: 중력 2600, 감쇠 1.1, 포인터 가속도 입력, 각도 제한 없음)로 흔들리며 그림도 같은 각도로 회전한다. 포인터를 빠르게 휘두르면 진자가 꼭대기를 넘어 한 바퀴 돈다. 물리 좌표(발)는 회전 전 위치를 쓰고 회전은 렌더링에서만 적용하므로 안테나 끝이 항상 포인터에 고정되며, 놓는 순간에는 회전된 실제 발 위치에서 낙하를 시작한다. 포인터 속도 1000px/s 초과분을 누적해 900을 넘으면 `dizzy`(눈 빙글빙글, `dizzy-v1`)로 바뀌고, 포인터가 잠잠해진 뒤 4.5초에 걸쳐 풀린다. 상주 모드는 놓은 자리에서 물리 동작을 계속하고, 알림 전용 모드는 놓은 위치를 저장한다.
- 알림·메뉴의 hover 중에는 새 자율 이동을 시작하지 않는다.
- 동작 줄이기는 정지 포즈를 사용하되 클릭 반응의 종료 시간은 계속 흐른다.
- 화면 배율 변경 시 해당 해상도의 캐시를 사용한다. 모니터가 제거되면 사용 가능한 모니터로 복구한다.
- 네이티브 창의 입력 통과는 실제 캐릭터 영역에만 해제한다. Windows에서는 WS_EX_LAYERED를 유지하면서 WS_EX_TRANSPARENT만 변경한다.

## 화면 전체 활동과 확인 반응 (2026-10-01)

- 크기는 0.5~5배이며 별도 245px 상한은 없다. 팝업 뷰포트 높이와 클릭 영역도 크기에 맞춰 갱신한다.
- 상주 모드에서 활동 범위를 메인/모든 모니터로 설정한다. 메인 제한은 드래그에도 적용하며, 맞닿은 모니터를 건너갈 때 OS 전역 좌표와 목적지 배율을 사용한다.
- `activity.rs`: 최대화/분할 레이아웃에서 줄 타기, 상단 매달림·옆 이동·휴식·하강, 옆 빼꼼, 분할선 구경. 알림/드래그/메뉴/동작 줄이기/창 배치 변경으로 중단한다.
- `crossing.rs`: 맞닿은 화면 사이 이동. 높이가 다른 바닥은 공통 표시 구간까지 줄로 이동한 뒤 건너간다. 떨어져 배치된 모니터를 순간이동하지 않는다.
- 근처 커서를 같은 지지면 안에서 따라가고, 5초 추적 뒤 휴식한다. 공중으로 걷거나 멀리 있는 커서를 쫓지 않는다.
- 창 끝의 지지는 몸 반폭과 분리한 발 반폭(크기의 0.07)을 사용한다. 보이는 작은/비활성 창 윗변도 후보이며 Z 순서와 앞 창의 가림은 유지한다.
- 수동 고낙차(몸 높이 1.2배 초과)는 `hurt`로 회복한다. 낮은 낙하·의도한 점프는 일반 착지다.
- `tickle.rs`: 누적 간지럽히기/길게 누르기 후 `enough`와 “이제 그만!”, 6초 쿨다운. 클릭 메뉴에 동작 선택 항목은 없다.
- 타이머 저장 성공 후에만 `ack` 확인 동작을 예약한다. 설정/우클릭/트레이가 동일 명령을 사용한다. 알림 전용에서도 잠깐 보이고 종료 후 숨으며 전체화면 숨김 설정은 유지한다.
- 새 알림 말풍선은 0.42초 팝 애니메이션을 한 번 재생한 뒤 기존 0.65초 색상 점멸을 이어간다. 알림 ID별 중복 재생 방지, 고정 클릭 영역, 앱/OS 동작 줄이기를 함께 적용한다.
- 온보딩 완료 후 정상 실행·업데이트 재실행은 설정창을 띄우지 않는다. 미완료 온보딩 또는 명시적 `--settings`/트레이 설정 열기만 표시한다.

## 비용 제어

주 실행 루프는 60Hz를 목표로 16.67ms 마감 시각을 사용하고 UI 스레드 작업은 한 번에 하나만 예약한다. 창 목록은 150ms 간격으로 갱신한다. 같은 그림·배치일 때 다시 그리지 않고, 같은 창 위치·크기·입력 통과 상태를 반복 설정하지 않는다. SVG 프레임 비트맵 캐시는 최대 16개·96MiB다. 5배/Retina의 한 걷기 주기가 캐시에 들어가도록 하며 실제 표시 빈도는 하드웨어·OS·그림 준비 시간에 영향을 받는다.

`native_pet_metrics`는 렌더러 종류, 그린 횟수, 가동 시간과 캐시 제한을 반환한다. 실제 팝업에서는 약 4MB의 개발 미리보기 아틀라스 JS를 로딩하지 않는다. 이는 로딩 경로 확인 결과이며 CPU·메모리가 특정 비율로 줄었다는 벤치마크 결과는 아니다.

## 검증

```sh
pnpm typecheck
pnpm build
node --test tests/pet-gait.test.mjs tests/pet-vector.test.mjs tests/pet-behaviors.test.mjs tests/pet-layout.test.mjs tests/pet-surfaces.test.mjs
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
node scripts/check-ui-browser.mjs
```

브라우저 검증은 Chrome이 필요하며 `CHROME_PATH`로 경로를 지정할 수 있다. 캡처는 OS 임시 폴더의 `ddoktti-ui-review`에 저장한다.

macOS/Windows의 독립된 개발용 실행 검증:

```sh
pnpm tauri build --debug --no-bundle --config '{"identifier":"kr.co.plead.ddoktti-here.native-smoke","bundle":{"createUpdaterArtifacts":false}}'
apps/desktop/src-tauri/target/debug/ddoktti-here --native-smoke
```

Windows에서는 마지막 실행 파일에 `.exe`를 붙인다. 테스트 식별자와 실행 인자가 모두 있어야 동작하며 릴리즈 빌드에는 테스트 모드가 없다. 계정 수신 서비스를 시작하지 않고 별도 설정 공간에서 걷기·달리기·졸기·클릭 반응·Slack/Calendar/타이머/스트레칭 샘플 알림을 재생한 뒤 종료한다. 실제 서비스 수신 검증을 대신하지 않는다.

Windows의 독립된 테스트 데스크톱/VM에서는 다음 명령으로 반복 실행과 실제 마우스 입력을 검사할 수 있다. `-TestInput`은 커서를 움직이고 버튼을 누르므로 검증 중에는 다른 작업을 하지 않는다. 종료 코드, 네이티브 창 존재, 렌더링 결과, 졸기 클릭 후 놀라기, 우클릭 메뉴, 드래그 상태를 검사한다. 로그는 출력된 임시 폴더에 남긴다.

```powershell
& .\scripts\check-native-windows.ps1 -ExePath .\apps\desktop\src-tauri\target\debug\ddoktti-here.exe -Repeat 3 -TestInput
```

설정 파일의 두 WebView는 `create: false`로 두고 `setup`에서 상태 등록 → 네이티브 창 준비 → WebView 생성 → 배치 및 실행 루프 시작 순서로 생성한다. Windows WebView2는 다른 창을 생성하는 중에도 IPC를 처리하므로 상태 등록 전에 HTML을 로딩하면 `state() called before manage()`로 종료될 수 있다. 이 순서를 유지한다.

2026-09-30 확인: macOS 네이티브 실행 및 렌더링 오류 검사, Rust 이동/아트 테스트, 브라우저 팝업·개발 미리보기 검증. Windows 11 ARM VM에서 x64 실행 파일의 단위 테스트 31개, 반복 실행 및 마우스 입력 검증도 통과했다. [Windows 검증 기록](windows-validation.md)에 환경과 제한을 기록했다. 혼합 DPI 다중 모니터, Spaces·절전·잠금 및 실제 계정 수신은 아직 검증하지 않았다. Windows와 macOS CI에서 Rust 테스트와 프런트엔드 검사를 실행하도록 구성했다.

## 다중 모니터 좌표와 Slack 포커스

macOS에서는 화면 전역 좌표는 논리 포인트이고, Tao 커서 API는 주 모니터 배율로 환산한 픽셀을 반환한다. 커서·드래그 시작점·히트 영역은 논리 포인트로 맞추고, 모니터별 물리 픽셀은 해당 모니터 배율로 변환한다. 창 위치·크기는 macOS에 LogicalPosition/LogicalSize로 전달하여 이전 화면 배율의 영향을 피한다. 렌더링은 목적지 배율의 픽셀 해상도를 유지한다. Windows는 전역 물리 픽셀 좌표를 유지한다.

배치 직후 창 위치를 읽으면 비동기 이동 이전 값이 돌아올 수 있으므로 마지막 요청한 모니터와 발 위치를 물리 엔진의 기준으로 사용한다. smoke 검사는 연결된 각 화면에서 이동 후 위치 유지와 걷기를 확인한다.

Slack 포커스 시 새 Slack 알림은 성공 처리하여 중계 서버에 ACK하며, 이미 표시 중인 Slack 알림도 닫는다. 다른 종류의 알림은 유지한다. macOS 공식 Slack은 `com.tinyspeck.slackmacgap`으로 확인한다. Windows는 `slack.exe` 또는 지원 브라우저의 활성 창 제목 중 독립적인 `Slack`/`슬랙` 구간으로 식별한다. PWA와 활성 Slack 탭을 지원하며, 제목만으로 판별하는 브라우저 방식은 URL 검증이 아니므로 제목이 같은 다른 페이지와 완벽히 구분할 수 없다. 창 제목은 저장·전송하지 않는다.

### 입력 감시와 UI 잠금 순서

백그라운드 입력 감시에서 Tauri 모니터/창 API를 호출하면 UI 스레드 응답을 동기적으로 기다릴 수 있다. 따라서 `Companion` 상태 잠금을 잡은 상태에서는 이 API를 호출하지 않는다. 2026-09-30 멈춤 사례는 입력 감시가 상태 잠금을 잡고 `primary_monitor`를 기다리는 동안 UI의 native tick이 같은 잠금을 기다린 교착 상태였다. 프로세스 스택 샘플로 확인했으며, 창 조회를 모두 잠금 밖에서 끝낸 뒤 히트 영역 판정에만 잠금을 사용하도록 수정했다.

네이티브 smoke는 실제 `companion::start` 입력/포커스 감시를 함께 실행한다. UI가 멈춰 검사가 무한 대기하지 않도록 60초 watchdog이 실패 종료한다. 계정 연결 서비스는 시작하지 않는다.


### 2026-10-01 실행 확인

macOS의 실제 2개 모니터(1×/2×, 서로 다른 작업영역 높이)에서 이동 후 화면 유지와 자율 경계 통과를 확인했다. 격리된 최적화 개발 빌드(`CARGO_PROFILE_DEV_OPT_LEVEL=2`)의 스케줄러는 약 59.9회/초였고, 걷기/달리기는 2초 동안 약 120회 그렸다. 이는 해당 환경의 단기 측정이며 모든 기기의 프레임 보장은 아니다. 타이머 저장 성공/잘못된 값 거부, 알림 전용 확인 후 숨김, 5배 네이티브 렌더링도 통과했다. 비최적화 개발 빌드는 약 45회/초였으므로 성능 평가는 최적화 빌드와 구분한다.

Rust macOS 54개·Windows 53개와 Node 44개 검사, HTML 말풍선/설정 브라우저 검사, 9장면 미리보기 검사 통과. Google의 실제 일정 전송은 이번 단위/화면 검사에 포함하지 않았다. 공개 배포 버전은 별도 릴리스 전까지 기존 버전을 유지한다.

Windows 11 ARM VM의 x64 최적화 빌드도 2회 정상 종료했다. 스케줄러 약 59.6/59.5회/초, 졸기 클릭 깨우기·우클릭·드래그·타이머 확인·알림 전용 자동 숨김·5배 표시가 통과했다. VM은 모니터 1개여서 실제 Windows 다중 모니터 통과는 미검증이며 혼합 DPI/높이 차이 경로는 단위 검사로 확인했다.


### 등반 앵커 표시 순서 보정

macOS의 Tauri 창 이동/크기 변경은 메인 큐에 예약되는 반면 이전 CALayer 내용 갱신은 즉시 실행됐다. 등반 프레임별 캔버스 원점이 달라질 때 새 로프가 이전 창 좌표에 표시될 수 있었다. 이제 NSWindow 좌표·크기와 CALayer 내용을 같은 표시 단계에서 동기 적용한다. Windows도 UpdateLayeredWindow에 목적지 좌표와 크기·픽셀을 함께 전달한다. 그림이 같고 위치만 바뀔 때는 이동만 수행한다. 원화 프레임을 사용한 1×/2×·좌우 반전·음수 모니터 좌표의 앵커 고정 회귀 검사를 추가했다.

후속 검증에서는 정장 음영 정리와 앵커 동기 표시를 포함한 macOS 빌드가 실제 두 모니터 유지·자율 이동, 타이머 확인, 알림 전용 숨김, 5배 렌더링을 통과했고 스케줄러는 60.0회/초였다. Windows VM도 입력을 포함한 네이티브 검사를 통과했으며 58.9회/초였다. Windows VM은 모니터 한 개이므로 실제 다중 모니터 검증은 macOS 결과와 좌표 단위 검사로 한정한다.

### 포인터·반응 후속 정리

포인터 추적은 보폭에 맞춘 달리기를 사용하며 0.55배 몸 크기에서 멈춘다. 다시 달리기 시작하는 거리는 0.72배로 두어 경계에서 동작이 떨리지 않게 한다. 가까이서는 `curious`를 포인터 방향으로 반전하고, 추적/주시 중 임의의 자율 동작을 고르지 않는다. 기존 지지면 경계는 유지한다.

간지럽힘 누적 기준은 3으로 낮추고 누르고 있을 때는 누적량이 감소하지 않는다. 반응 시간은 사용자 애니메이션 속도와 무관하며, 웃음 뒤 `shy` 대신 `relieved`로 진정한다. 작은 반응은 HTML의 불투명 말풍선으로 표시하고 화면 경계를 기준으로 배치한다. 메뉴가 열려 있으면 반응 말풍선을 숨긴다.

Google loopback 인증 응답 화면은 앱에 포함된 반응형 HTML을 사용한다. 토큰 교환 전이므로 완료를 단정하지 않고 인증 응답 수신과 앱 내 최종 확인을 안내한다. Slack 중계 서버는 별도 저장소의 동일 디자인을 사용하며 승인·취소·실패를 구분한다.

### 포인터 추적 중 창 끝 반응

추적 전용 `follow_step`도 지지면 경계에 도달하면 좌표 제한만 하지 않고 `Wobble`로 전환한다. 기존 0.65초 주춤 뒤 방향 전환 또는 창 위에서의 낙하를 그대로 사용한다. 경계 감지 시 추적을 3초 쉬고 걷기로 전환해, 돌아선 직후 포인터가 방향을 다시 뒤집어 경계에 붙는 것을 방지한다. 화면 바닥 끝에서는 낙하 없이 돌아선다. 좌우 창 끝·추적 일시정지 후 후퇴·화면 끝 비낙하 회귀 검사를 추가했다.

### 상단 부착·방향·반복 주기

상단 순회는 작업영역의 `y=8` 대신 실제 모니터 상단을 사용한다. `ceiling=(monitor.y-workarea.y)/scale`은 macOS 메뉴 막대가 있으면 음수일 수 있다. 손 랜드마크로 발 기준점까지의 거리를 계산하며 SVG의 투명 여백은 화면 밖 음수 y에 놓일 수 있다. 0/24/38px 상단 여백, 여러 캐릭터 크기, 두 매달리기 프레임의 손 접점을 검사한다.

매달린 채 이동할 때도 실제 수평 이동 부호로 좌우 반전한다. 정지 시 마지막 방향을 유지한다. 놀이 중에는 다음 놀이 대기 시간이 줄어들지 않으며, 종료 후 60~120초 휴식 시간을 다시 준다. 같은 놀이를 연속으로 고르지 않고 좌우 진입 방향을 번갈아 사용한다. 단일 최대화에서는 분할 경계 놀이를 후보에서 제외한다. 관련 검사를 포함한 Rust 60개가 통과했다.

### macOS 메뉴 막대 위 매달림 잘림 수정 (2026-10-01)

macOS에서 최대화 창 줄타기 때 줄과 캐릭터 윗부분이 잘리던 문제의 원인은 두 가지였다. 첫째, `alwaysOnTop`의 NSFloatingWindowLevel(3)에서는 AppKit이 `setFrame:`/`setFrameOrigin:`을 모두 메뉴 막대 아래로 강제 보정해 캔버스가 요청 좌표보다 메뉴 막대 높이만큼 아래로 밀렸다(실측: 3840×2160, 메뉴 막대 30pt). 둘째, 놀이 중 이웃 모니터 보호용 지우기가 모니터가 아닌 작업영역 기준이어서 메뉴 막대 구간(`ceiling<0`)의 손·줄 고리를 지웠다.

네이티브 캐릭터 창은 macOS에서 `platform::on_top`이 NSStatusWindowLevel(25)을 직접 설정한다. 이 레벨은 프레임 보정이 없고 메뉴 막대·Dock 위에 그려진다. 지우기는 `clip_to_display`가 `monitor.position()/size()` 물리 경계를 사용하며, 메뉴 막대 구간을 유지하고 이웃 모니터 쪽만 지우는 검사를 추가했다. Windows 경로는 변경 없다.

### 다중 모니터 깜빡임: 캔버스 창을 디스플레이별로 분리 (2026-10-01)

1배율 4K + 2배율 맥북 배치에서 캐릭터 창이 두 디스플레이에 걸치면(빼꼼, 모니터 사이 점프·줄타기) 매 프레임 깜빡였다. `DDOKTTI_TRACE=1` 프레임 추적으로 앱 내부 좌표·모드·표시 상태는 60fps로 안정적임을 확인했고, 남는 원인은 배율이 다른 두 화면에 걸친 레이어 호스팅 창을 macOS가 매 프레임 다시 백킹하는 동작이다. 창 레벨 보정(statusBar)만으로는 사라지지 않았다.

해결: 네이티브 창은 항상 현재 모니터 안에만 둔다. `geometry()`가 모니터별 물리 좌표와 스탬프를 계산하고 `crop_to_display`로 창을 디스플레이 경계에 맞춰 자르며, `paint()`가 같은 입력으로 캔버스를 그린다. 캔버스가 이웃 디스플레이로 넘어가는 부분은 두 번째 창 `pet-native-2`(overflow)가 그 디스플레이의 배율로 따로 그린다. 보조 창은 항상 입력을 통과시키며 필요 없으면 숨긴다. 매달림·빼꼼처럼 놀이 중 디스플레이 경계를 넘는 부분도 보조 창이 이웃 화면에 그리되, 활동 범위가 메인 모니터 전용이면 이웃 화면에는 그리지 않는다. 이 분리는 macOS에서만 켜고, Windows는 놀이 중 지우기 범위만 유지한다.

진단용 추적: `DDOKTTI_TRACE=1`로 실행하면 stderr에 프레임마다 틱 시간·그리기 시간·모니터·배율·모드·창 좌표를 출력한다. 본문·토큰은 기록하지 않는다. 릴리즈 실측(2026-10-01): 4K 1배율 틱 2~4ms, 맥북 2배율 틱 5~7ms, 두 화면 모두 좌표 갱신 17ms(60fps). 디버그 빌드는 합성이 최적화되지 않아 레티나에서 20fps로 떨어지므로 성능 판단에 쓰지 않는다.

### 모니터 사이 이동이 시작되지 않던 문제 (2026-10-01)

이동 판정은 `on_floor()`(Grounded)와 "가장자리에서 그 방향을 보고 있음"을 같은 틱에 요구했다. 그러나 걷다가 가장자리에 닿으면 물리가 같은 틱에 `Wobble`로 들어가고, 0.65초 뒤 방향을 뒤집으며 Grounded로 돌아오므로 조건이 성립하는 순간이 없었다. 낙하 착지로 우연히 가장자리에 서는 경우만 이동했다. `Physics::edge_departure`가 Grounded 또는 방향이 뒤집히기 전의 Wobble에서 바닥 가장자리 도달 방향을 돌려주고, `mod.rs`는 이 값으로 `Crossing::new`를 시도한다. 이웃이 없으면 대기를 35초가 아닌 3초로 두어 반대쪽 가장자리에서 다시 시도한다.

### 모니터 경계 줄타기와 주변 창의 상태 분리 (2026-10-01)

화면 사이 이동 경로는 명시한 모니터와 전역 발 좌표로 `world_at`을 조회한다. 매 프레임 팝업 이동 후 위치를 재조회하고 일반 `Physics::new`로 초기화하던 경로를 없앴다. `Physics::guide`는 창 부착·발판·점프 계획을 해제하고 경로 좌표를 클램프 없이 유지한다. 창 정보를 갱신할 때도 경로가 진행 중이면 일반 창 이동 보정을 적용하지 않는다. 경로 종료/사용자 중단 시에만 일반 물리를 다시 활성화한다.

경계 이동은 바닥에 서 있을 때만 시작하며, 창 등반 중 끼어들지 않는다. 진행 중 포인터가 우연히 캐릭터를 스치는 것만으로 경로를 취소하지 않고, 실제 드래그·메뉴 요청·알림 등은 기존처럼 중단한다. 출발/도착 모니터 어느 쪽이 사라져도 경로를 취소한다. 포인터 추적도 진행 중 경로에 개입하지 않는다. 움직이거나 순서가 바뀌는 주변 창과 혼합 배율·좌우 이동을 결합한 회귀 검사를 추가했다. 사용자가 보고한 실제 환경에서의 재현 여부는 단위 검증과 구분한다.

### 쓰다듬기

버튼을 누르지 않은 채 캐릭터 위에서 부드럽게 수평 왕복하면 `petted` 반응과 작은 말풍선이 나온다. 최소 왕복 길이, 속도 상한, 정지 시간 제한과 4초 재반응 대기를 사용한다. 정지 포인터·작은 떨림·빠른 통과·클릭·드래그는 제외한다. 알림/메뉴/등반 중에는 시작하지 않는다. 표정은 `petted-v1`(홍조·감은 눈, 0.45초 간격 4프레임 루프)을 사용하며 클릭 간지럽힘 누적에는 영향을 주지 않는다.

### Windows 네이티브 캔버스 DPI 소유권

Tao 0.37.1의 `WM_DPICHANGED` 처리는 이전 창 크기를 새 배율로 다시 환산한다. 네이티브 캐릭터는 이미 목적지 모니터 배율로 픽셀 버퍼와 창 크기를 계산하므로 이 처리가 겹치면 낮은 DPI에서 창이 두 번 축소되어 기존 픽셀 버퍼가 잘릴 수 있다. 캐릭터 HWND에만 UI 스레드에서 서브클래스를 설치해 `WM_DPICHANGED` 자동 리사이즈를 차단한다. 배율 적용은 렌더러와 `UpdateLayeredWindow`가 수행한다. 해당 창에서 Tao의 내부 배율 값은 사용하지 않는다. 설정과 HTML 팝업은 기존 자동 DPI 처리를 유지한다. `WM_NCDESTROY`에서 서브클래스를 제거한다.

후속 검증: Rust 63개, Node 순수 단위 검사 45개, 타입 검사와 프런트엔드 빌드, SVG 정리 검사를 통과했다. 생성된 5프레임과 쓰다듬기 재사용 표정은 벡터 렌더링 결과로 시각 확인했다. Windows x64 교차 빌드(실행 파일 링크 포함)도 통과했다. 이번 실행 환경에서는 로컬 HTTP 서버 생성이 `EPERM`으로 제한되어 HTTP 통합/브라우저 검사를 실행하지 못했다. 실제 Windows의 서로 다른 DPI 모니터 간 이동 및 사용자 환경의 떨림 재현 검증은 아직 수행하지 않았으며, 과거 Mac/VM 실행 결과를 이번 수정의 실기 검증으로 간주하지 않는다.

### 로컬 실행 빌드 주의

일반 `cargo build`는 개발 URL (`localhost:1420`)을 사용할 수 있다. 개발 서버를 실행하지 않은 채 이 바이너리만 안내하면 HTML 준비 신호를 받지 못해 캐릭터가 숨겨질 수 있다. 사용자에게 보여줄 로컬 빌드는 `pnpm tauri build --debug --bundles app`으로 프런트엔드 리소스와 custom-protocol을 포함해 만든다. 로컬 빌드에서는 `bundle.createUpdaterArtifacts=false`를 지정하며 실제 배포 서명 빌드와 구분한다. 개발 서버 연결과 Slack/Google 서비스 연결은 다르다. 외부 서비스 수신은 별도 스레드에서 처리하므로 서비스 장애가 로컬 캐릭터·타이머 실행을 막으면 안 된다.

### v0.1.15 서비스 장애 및 산책 방향

Slack/Google 수신 스레드는 로컬 캐릭터·타이머 준비 상태를 변경하지 않는다. 연결 장애는 설정의 상태 문자열로 계속 표시하고, 캐릭터에는 4초짜리 작은 말풍선을 한 번 예약한다. 정상 알림·드래그·메뉴·등반을 방해하지 않으며 방해 금지/전체화면 숨김 설정을 따른다. 20초 안에 표시하지 못한 안내는 폐기한다. 동일 장애의 반복 재시도에는 다시 표시하지 않고, 연결이 오락가락할 때도 서비스별 5분 제한을 둔다. 복구는 조용히 반영한다. 서버 오류에는 자동 재시도하고 인증 만료에는 다시 연결을 안내한다. Calendar의 기존 캐시 일정은 장애 중에도 유지된다. 서비스 mutex를 해제한 뒤 Native에 상태를 전달한다.

일반 산책은 시작 시 오른쪽을 기본으로 하고 이후 방향을 유지하던 방식에서, 초기에는 화면 중앙을 향하고 새 산책마다 좌우를 선택하는 방식으로 변경했다. 열린 공간에서는 같은 방향 선택을 최대 2회까지 허용하고, 발판/화면 끝 근처에서는 안쪽을 우선한다. 진행 중인 등반 경로와 포인터 추적에는 적용하지 않는다. 편향된 난수 입력에서도 좌우 산책이 나오는지, 가장자리에서 돌아서는지, 낙하·등반 접근을 덮어쓰지 않는지 회귀 검사한다.

최종 소스 검증: Rust 67개·Node 순수 단위 검사 45개, 타입 검사와 프런트엔드 빌드, Windows x64 실행 파일 교차 링크를 통과했다. 실제 혼합 DPI Windows 동작, 최신 Mac 앱 GUI 실행, 로컬 HTTP 통합 검사는 현재 실행 환경 제한으로 미검증이다. 버전 파일과 릴리스 노트는 0.1.15로 준비했으나 `.git` 읽기 전용 제한 때문에 커밋·태그·공개 릴리스는 수행하지 못했다.

### 창에서 내려오기: 줄 하강과 모서리 점프 (2026-10-01)

캐릭터가 창 위로 올라간 뒤 좀처럼 내려오지 않았다. 쿨다운마다 `seek_rope`가 먼저 실행되어 머리 위에 창이 있으면 거의 항상 올라갔고, 내려오는 경로는 220px 이내 아래 발판 점프, 가장자리 휘청임의 18% 미끄러짐, 창이 사라질 때의 낙하뿐이었다. 높은 창에서 바닥까지 가는 길은 사실상 사고(`Hurt`)였다.

`Physics`에 창 위 체류 시간(`perch`, 바닥에 서면 0)과 고도로 계산하는 `descent_urge`를 추가했다. 25초까지는 0이고 120초에 1에 도달하며 고도에 따라 0.5~1배로 조정한다. 쿨다운이 끝날 때 이 확률로 "내려가기"를 고르고, 아니면 기존처럼 줄 탐색을 한다. 내려가기는 두 가지 수단 중 하나다.

- **모서리 점프**: `jump_plans`가 아래 방향 발판과 함께, 지지 창 모서리 바깥의 바닥(220px 이내, 모서리에서 몸 폭 2.5배 이내)을 후보로 넣는다. `drop_plan`은 그중 아래쪽만 고른다. 의도된 점프이므로 `Hurt`가 아니다. 계획의 `id`가 `None`이면 바닥이며 사전 검증을 생략한다.
- **줄 하강**: `descent_target`이 지지 창의 노출된 모서리(`edge_landing`)와 그 아래 벽이 앞 창에 가려지지 않았는지(`wall_visible`), 착지점(`floor_below`: 매단 x 아래 첫 발판 또는 바닥)까지 키 이상 떨어지는지 확인한다. `approach_descent`로 모서리까지 걸어간 뒤 `Lower`(pull을 역재생, 0.7초, 줄이 고정점에서 풀려 나옴) → `Descend`(climb 프레임 3→2→0→1 역재생, `climb_distance`와 같은 박자로 하강) → `Land`로 이어진다. 창이 움직이면 등반처럼 모서리를 따라가고, 닫히거나 벽이 가려지면 낙하한다. 감소된 모션에서는 바로 아래 발판으로 해결한다.

`climb_visible`은 `wall_visible(w, side, top, bottom)`의 특수형으로 바꿨다. `art.rs`와 `pet-vector.ts`에 `lower`/`descend` 포즈를 추가했으며 새 아트는 없다. 모션 갤러리와 창 위 산책 미리보기에도 두 동작을 넣었다. 휘청임 미끄러짐과 `Hurt`는 그대로 두어 의도된 하강과 대비되는 드문 사고로 남긴다.

### 주변 창과 자리 비움에 반응 (2026-10-02)

입력 내용이나 창 제목을 읽지 않는 범위에서, 사람이 캐릭터 주변에서 하는 일에 반응한다.

- `Physics::update`가 `Nudge`를 돌려준다. 서 있는 지지 창이 한 번의 감지 간격(150ms)에 몸 크기의 15% 이상 움직이면 `Ride`, 다른 창이 그만큼 움직여 몸 주변(몸 크기의 50% 여유) 상자와 겹치면 `Brush`, 지지 창이 닫히거나 줄어들거나 가려져 떨어지면 `Lost`(`lost_support`에 남겨 착지 때 소비)다. 창이 새로 나타나는 것은 반응하지 않는다. 등반·점프 중과 사용자 드래그 리셋은 보고하지 않는다.
- `mod.rs`는 평온한 상태(상주, 물리 바쁨 아님, 드래그·메뉴·알림·반응·놀이·경계 이동·포인터 추적 아님)에서만 반응한다. `Ride`→`surprised`(15초 간격), `Brush`→`curious`(10초 간격), `Lost` 착지→`sulking`과 "앗, 발판이 없어졌어요…" 말풍선. 말풍선은 알림 쉬기 중에는 생략한다.
- `presence.rs`는 `companion::idle_seconds()`(스트레칭 안내와 같은 함수, macOS `CGEventSourceSecondsSinceLastEventType`, Windows `GetLastInputInfo`)만 입력으로 받는다. 10분 무입력이면 `Doze`, 그 뒤 첫 입력이면 `Return(비운 시간)`. 조는 동안은 새 행동을 고르지 않고 `sleepy`를 유지하며 줄 접근도 멈춘다. 돌아오면 30분 미만은 `greeting`+"다녀오셨어요?", 30분 이상은 `excited`+"오랜만이에요! 기다렸어요.". 캐릭터를 클릭·드래그하면 조용히 깬다(기존 "앗, 깼어요!" 경로 유지).

### 발표 중 숨기기: 미러링과 프로젝터 감지 (2026-10-02)

`presenting.rs`는 권한 없이 읽을 수 있는 두 신호로 "지금 화면을 남에게 보여 주는 중"을 판단한다. 참이면 전체 화면 숨기기와 같은 방식으로 캐릭터와 알림을 숨기고 타이머는 계속 간다(`hide_presenting`, 기본 켜짐).

- **미러링**: macOS `CGDisplayIsInMirrorSet`, Windows `QueryDisplayConfig`의 토폴로지가 복제이거나 두 경로가 같은 소스를 쓰는 경우.
- **프로젝터 식별**: EDID 이름(macOS `NSScreen.localizedName`, Windows `DISPLAYCONFIG_TARGET_DEVICE_NAME`), PNP 제조사 코드(macOS `CGDisplayVendorNumber`, Windows 장치 경로의 `DISPLAY#XXX….`), 물리 크기 유무(macOS `CGDisplayScreenSize`)를 본다. 규칙은 linuxhw/EDID 데이터베이스(약 3.9만 건)에서 실제 프로젝터 항목을 조사해 정했다.
  - 이름에 단어 `PJ`(BenQ·Sony·ViewSonic·Casio·Acer "XGA PJ"), `PROJECTOR`(LG·Hitachi·MStar), `EPSON`(Epson은 PNP가 `SEC`라 이름으로 구분), `VPL`(Sony), 그리고 XGIMI·Nebula·JMGO·Dangbei·Formovie·Yaber·Wanbo·Vivitek·InFocus·CineBeam·Freestyle. 단어 경계를 보므로 LG 모니터 `22MP55PJ`는 제외된다.
  - 모델 접두사 `NP-`(NEC), `PT-`(Panasonic), `VPL`, `EB-`/`EH-`/`EF-`(Epson). LG 코드 `GSM` + `HU`/`PF`/`HF`/`BU`+숫자.
  - 프로젝터 전용 제조사 코드 `EPS`/`EHJ`, `OTM`/`OPT`(Optoma는 이름이 "1080P"·"WXGA"뿐), `GMI`(XGIMI), `HTC`(Hitachi 프로젝터, 모니터는 `HEC`/`HIT`), `CAS`, `VIT`, `IFS`, `CHR`.
  - 해상도만 있는 이름(`XGA`, `WUXGA`, `1080P`…)은 물리 크기가 없거나 `GRU`(Grundig)일 때만. "크기 없음" 단독은 TV(`SONY TV`, `LG TV`), AV 리시버(`AVR`), `SyncMaster`에도 해당해 쓰지 않는다.
  - 내장 디스플레이는 항상 제외한다. 새 디스플레이 연결 이벤트 자체는 신호로 쓰지 않는다(새 모니터일 수 있음).
- NSScreen은 UI 스레드에서만 다루므로 워커가 `run_on_main_thread`로 조회를 예약하고 다음 틱에 `AtomicBool` 결과를 읽는다. 디스플레이 구성은 드물게 바뀌므로 5초마다 갱신한다. 이름·코드는 메모리에서 비교만 하고 저장·전송하지 않는다. 숨김 여부는 `State::hidden()` 한 곳(전체 화면·발표 중)에서 정하고 네이티브 틱과 overlay의 알림음이 같은 값을 쓴다. Windows 조회는 `windows` 크레이트의 `Win32_Devices_Display` 타입을 쓴다.
- 한계: 확장 모드에서 규칙에 없는 프로젝터는 놓친다. Zoom·Meet 화면 공유는 OS가 알려 주지 않는다. Windows 구현은 CI의 Windows 검사로 컴파일을 확인하며 실기 검증은 별도다.

### 대기·졸기 모션, 등반 후 표정, 드래그 회전 캔버스 (2026-10-02)

- **대기(idle)**: 안도감 시트의 기본 자세(emotions-v2-18)를 고정으로 쓰던 것을, 3.4초 주기 ±1.4 단위의 숨쉬기(`lift`)와 4.1초마다 0.15초 동안 같은 자세의 눈 감은 그림(emotions-v2-17)으로 깜빡이는 모션으로 바꿨다. 감소된 모션에서는 정지 그림을 유지한다. `pet-vector.ts`도 같다.
- **졸기(sleepy)**: 하품 4장(1.7초 간격) 뒤 마지막 장에서 멈추던 것을, 이후에는 눈 감은 두 장(10·11)을 1.4초마다 번갈아 보여 주고 3.6초 주기로 숨 쉬는 무한 루프로 바꿨다. 자리 비움으로 오래 졸 때 정지 이미지가 되지 않는다.
- **등반 후**: `Pull`이 끝나면 `Land`(웅크린 착지)와 "안도감" 대신 바로 `Grounded`로 들어가고 `Physics::climbed`를 세운다. `mod.rs`가 이를 소비해 "뿌듯함"(proud)을 재생한다. 줄 하강의 착지도 같다. 줄에서 내려서는 것은 의도된 동작이라 웅크림·안도감을 거치지 않는다. 뛰어내리기(hop)만 점프 착지(`Land`)를 유지한다.
- **드래그 회전 캔버스**: 안테나에 매달려 흔들릴 때 회전한 프레임의 경계 상자를 매 프레임 계산해 캔버스 크기가 각도마다 바뀌었다. Windows에서 빠르게 흔들면 크기 변경이 픽셀 갱신보다 늦어 몸 일부가 잘려 보였다. 이제 포인터(회전축)를 중심으로 어떤 각도에서도 프레임이 들어가는 정사각형(모서리까지의 최대 거리 기준)을 캔버스로 써서 흔드는 동안 크기가 바뀌지 않는다. 캔버스는 커지지만 드래그 중에만 해당한다. macOS 실행으로 회귀를 확인했고 Windows 실기 확인은 별도다.

### 창 주머니 탈출 (2026-10-02)

실제 창 배치 스냅샷(앞의 큰 창 왼쪽 모서리 → 줄로 작은 창 꼭대기 → 작은 창은 왼쪽 모서리가 화면 밖, 오른쪽 벽은 큰 창에 가려짐)에서 캐릭터가 큰 창을 줄로 내려온 직후 걷다가 그 벽에 손이 닿아 다시 기어오르는 일을 무한 반복했다. 10분 추적에서 8분 동안 한 창 꼭대기에 머문 원인이다.

- 벽에 부딪혀 시작하는 등반(`start_climb`)은 하강 욕구가 0.5 미만일 때만 한다. 내려오고 싶은 캐릭터는 방금 내려온 창을 다시 오르지 않고 발판 끝에서 돌아선다.
- 하강 욕구가 있는데 줄도 짧은 점프도 없는 상태(`no-way-down`)가 45초 이상 이어지면(`stuck`), 뛰어내리기 후보의 220px 범위 제한을 풀어 모서리 밖 바닥이나 먼 아래 발판으로 뛰어내린다. 의도된 점프라 `Hurt`가 아니라 `Land`로 착지한다.
- 같은 스냅샷을 Rust·Node 회귀 테스트로 두어 5분 안에 바닥에 닿고 재등반이 0회인지 확인한다. 추적 로그(`DDOKTTI_TRACE=1`)는 10초마다 지지 창·체류 시간·욕구·마지막 결정 이유·창 배치를 남긴다.

### 한쪽 쏠림 완화: 체류 균형 (2026-10-02)

12분 추적에서 캐릭터가 거의 내내 오른쪽에 있었다(평균 x 2978/3840). 로그의 결정 이유를 보면 오르내린 창 세 개가 모두 오른쪽 절반에 있어 줄 탐색이 늘 그쪽으로 데려갔다. 기분 탓이 아니라 창 배치에 따른 구조적 쏠림이다.

`Physics::balance`는 화면 중앙 기준 위치(-1~+1)를 약 300초 시정수로 평균한다. 바닥에서 새 산책 방향을 고를 때 `|balance| > 0.3`이면 네 번 중 세 번은 덜 머문 쪽으로 간다. 연속 같은 방향 제한은 이 편향에 양보하고, 발판·화면 끝 안쪽 우선 규칙은 그대로 적용한다. 창 위에서는 적용하지 않는다(줄과 모서리가 방향을 정한다). `pet-surfaces.ts`도 같은 균형값을 계산한다.

### 알림 포즈 반복 (2026-10-02)

알림 말풍선이 떠 있는 동안 캐릭터는 알림 시트의 4장을 2초 동안 한 번 재생하고 마지막 장에서 멈췄다. 말풍선은 몇 분씩 유지되므로 그동안 정지 이미지였다. 이제 2초의 소개 동작 뒤에는 `alert_loop`가 행마다 정한 두 장(Slack은 표지판 들기/가리키기, 일정·타이머·스트레칭은 마지막 두 장)을 0.8~1.3초 간격으로 번갈아 보여 준다(상하 흔들림 없음). 감소된 모션은 마지막 장을 유지한다. `pet-behaviors.ts`의 `alertLoop`가 같다.

### 자리 비움은 바로 이불 속으로 (2026-10-02)

10분 졸기 → 30분 이불이던 2단계를 없애고, 5분 무입력이면 바로 이불을 덮고 잔다(`Doze`→`asleep`). 졸기(`sleepy`)는 평소 행동 선택의 하나로만 남는다. 복귀 인사는 그대로 비운 시간 기준이다(30분 미만 "다녀오셨어요?", 이상 "오랜만이에요!").

### 프레임 전환 동작에서 상하 흔들림 제거 (2026-10-02)

대기(고개 갸웃·깜빡임), 졸기·이불 수면(끄덕임·수면 4장), 알림 반복(두 장 교대)에 코드로 더했던 숨쉬기 상하 이동(±1.2~1.4단위)을 모두 뺐다. 프레임 전환이 있는 동작은 그림 자체가 움직이므로 흔들림을 겹치면 떠 보인다. 점프·신남의 실제 뛰어오름(`lift`)은 그대로다.

### 갇힘 탈출 2차: 끝으로 걸어가 뛰어내리기 (2026-10-02)

v0.1.18에서도 창 위에서 내려오지 않는 경우가 남아 있었다. 원인은 셋이다. 점프 계획이 "옆으로 몸 폭 절반 이상" 떨어진 목표만 허용해 바로 아래 창·바닥으로는 계획이 생기지 않았고, 갇힘 시간(`stuck`)이 "길 없음" 결정이 난 구간에만 쌓여 45초에 늦게 도달했으며, 그 사이 욕구 굴림에 실패한 40%는 다시 위로 줄을 탔다.

- 아래 방향 목표의 최소 가로 거리를 발 폭의 2배로 줄이고, 아래 발판 후보에 "내 발판 양 끝 바깥쪽(끝 ± 몸 폭 절반)"을 추가했다. 발판 끝에서 바로 아래 창이나 바닥으로 뛰어내릴 수 있다.
- `stuck`은 하강 욕구가 0.5 이상이고 아직 경로(줄·점프)를 잡지 못한 동안 계속 쌓인다. 45초가 되면 `seek_corner`/`approach_corner`가 지금 선 발판 조각의 가까운 끝으로 걸어가 `drop_plan`(원거리 허용)으로 뛰어내린다.
- 하강 욕구가 0.5 이상이면 줄을 타고 올라가는 탐색(`seek_rope`)도 하지 않는다(벽 부딪힘 등반과 같은 기준).
- 회귀 테스트: 넓은 창 양 끝 바로 아래(100px)에 앞 창이 있어 줄은 너무 짧고 바닥은 멀어 예전엔 영영 못 내려오던 배치에서 4분 안에 내려온다.

### 갇힘 탈출 3차: 양 끝 시도와 상태 정리 (2026-10-02)

- 탈출 때 가까운 끝에서 뛰어내릴 곳이 없으면(예: 창이 화면 왼쪽 끝에 붙어 왼쪽 끝 바깥이 화면 밖) `corner_tried`에 기록하고 반대쪽 끝으로 걸어간다. 양 끝 모두 실패하면 기록을 비우고 다음 기회에 다시 시도한다. 회귀 테스트: 왼쪽 끝에 붙은 넓은 창에서 오른쪽 끝 아래 창으로 5분 안에 내려온다.
- `corner` 상태는 감소된 모션, 비자율(알림·메뉴·드래그), 포인터 추적의 발판 끝 휘청임에서도 `descent`와 같이 지운다.
- 점프 후보 계산은 자기 발판을 한 번만 구해 각 후보와 포물선 검사에 넘긴다.
- 사생활 모드(알림 내용 숨기기)에서는 일정 말풍선에 남은 시간 제목만 두고 시각 범위는 표시하지 않는다.
- 프리뷰의 클릭 동작은 `asleep`(이불 수면)도 깨우기로 본다.

### 투어: 끝까지 가로지르고 중간에 쉬기 (2026-10-02)

최대화 창에서의 투어는 윗변에 매달린 뒤 화면 가운데까지만 가고 12초가 지나면 내려왔다. 이제 올라간 쪽의 반대편 끝(가장자리에서 몸 폭 절반 안쪽)까지 가로지른다. 속도는 초당 몸 폭의 30%이고, 4.5초 이동 후 2.5초 멈춰 구경하는 리듬을 반복한다. 포인터가 근처 위쪽에 있으면 쉬지 않고 포인터를 따라간다. 반대편 끝에 닿으면 2.5초 쉬고 내려오며, 90초가 지나면 어디서든 내려온다(안전 상한). 하강 줄의 고정점은 현재 위치 위라서 어디서 내려와도 자연스럽다.
