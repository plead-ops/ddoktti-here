# 화면 전체 활동: 승인 및 구현 기록 (2026-10-01)

사용자 요청: 크기 5배, 메인/모든 모니터 활동 범위, 의상 상하 경계 보정, 최대화·분할 대응, 가까운 마우스 따라가기, 높은 낙하의 아야 반응, 실제 창 끝에 가까운 멈칫. 추가로 앞의 작은 창과 뒤의 비활성 창에도 올라가야 한다.

## 이번 단계

`/playground.html`에서 아래 9개 장면의 이동 경로·타이밍·크기를 검토한다. 실제 OS 창이나 계정 설정을 변경하지 않는 별도 진입점이다. 앱 런타임은 playground 모듈을 가져오지 않는다. 기존 `/motions.html`에서 링크로 진입할 수도 있다.

1. 줄 타고 상승 → 상단 이동 → 휴식 → 하강 → 착지
2. 상단 매달리기와 근접 커서 발견·짧게 따라오기
3. 옆에서 빼꼼
4. 분할 경계 구경
5. 근접 커서 따라가기: 거리 유지, 5초 추적 뒤 휴식, 같은 바닥에서만 이동
6. 낙하: 중력 이동, 실제 키 대비 낙차 1.2배를 기준으로 가벼운 착지 / 회복 구분
7. 창 끝: 기존 넓은 몸체 여백과 발 지지점 비교
8. 두 모니터: 메인 제한 / 모든 화면 이동 개념도
9. 앞 작은 창으로 등반 → 뒤 비활성 창의 노출된 윗변으로 점프

미리보기 설정: 0.5~5배, 창 배치, 활동 범위, 낙차, 밝은/어두운/격자 배경, 마우스 반응, 전체화면 숨김, 동작 줄이기, 접점 가이드. 시간 슬라이더·정지·느린 재생·한 프레임 이동 제공. 크기에 비해 위 공간이 없으면 겹친 창 장면에서는 올라가지 않고, 낙하 높이는 화면 안으로 제한한다.

## 승인 후 반영 상태

사용자가 9개 장면을 승인한 뒤 실제 네이티브 스케줄러에 반영했다. 활동/이동/입력 변경은 `native_pet/{activity,crossing,physics,tickle,mod}.rs`, 아트는 공통 SVG 아틀라스와 `scripts/pet-art-repairs.py`에 있다. 미리보기는 동일한 포즈를 사용하되 가상 경로를 재생하므로 OS 창 수집 검증을 대신하지 않는다.

- 0.5~5배, 메인/모든 모니터, 커서 따라가기 설정 반영.
- 앞 작은 창/뒤 비활성 창의 발 지지, 가림·순서·이동·닫힘과 좁은 선반 접근 검사.
- 상단/옆/분할 활동과 서로 다른 높이 모니터의 경계 이동.
- 높은 낙하 `hurt-v1` 5프레임, 매달림 13/15, 빼꼼 12, 타이머 `ack`, 과한 간지럽히기 `enough` 반영.
- 밑단 비교의 오른쪽은 실제 보정 SVG, 왼쪽은 복원한 선만 제외한 비교다. 보정 후 선을 중복으로 추가하지 않는다.
- 외곽선과 연결된 정장 영역을 구분하는 팔레트 처리를 적용하고 129프레임/첫 인사/아이콘을 재생성했다.
- 정상 시작 설정창 숨김, 60Hz 목표 네이티브 이동, 말풍선 출현 팝, 타이머 저장 확인을 함께 반영했다.

## 여러 시점의 일정 알림

일정 시작 0~1440분 전에 1~8개 시점을 추가/삭제한다. 0분은 시작 시각이다. 기본값과 기존 단일 설정은 유지하고 중복 분 값은 하나로 합친다. 이벤트 중복 제거는 기존 iCalUID/반복 일정 occurrence 기준을 유지하며 전달 ID에는 알림 시점을 추가한다. 각 시점은 한 번 전달되고, 다음 시점은 같은 일정의 이전 미확인/다시 알림을 교체한다. 절전·알림 중지 후에는 가장 최근 유효한 시점만 전달한다. 취소·거절·시간 변경 시 오래된 알림을 제거한다.

## 검증

`pnpm typecheck`, `pnpm build`, Rust 단위 검사, Node 단위 검사, `scripts/check-ui-browser.mjs`, `scripts/check-playground-browser.mjs`, 격리된 네이티브 smoke 앱. 실제 검증 환경과 제한은 [네이티브 렌더링](../native-rendering.md), [Windows 검증](../windows-validation.md)에 기록한다.

미리보기 캡처는 OS 임시 폴더 `ddoktti-playground-review`에 보관한다. 실제 Google 일정 수신은 저장된 샘플 이벤트에 대한 스케줄러 단위 검증과 구분한다.

추가 아트 정리: 드래그 4프레임의 어두운 정장 음영이 외곽선으로 바뀐 회귀를 수정했고, 걷기/달리기의 불필요한 덧선을 제거했다. 원본 비율과 전체 129프레임은 유지한다.

## 사용자 후속 수정 — 2026-10-01

- 별도 미리보기 승인을 생략하고 직접 반영하도록 요청받았다.
- 감정 20프레임 정장 밑단, 착지 옷깃, 아픈 착지 턱선 경계, 하품 입/손 2프레임을 정리했다.
- 포인터 추적은 달리기→가까이서 방향 주시, 거리 여유 구간과 기존 지지면 제한을 적용했다.
- 간지럽힘과 타이머 확인은 작은 불투명 말풍선으로 배치한다. 웃음 뒤 수줍음 전환을 없애고 누적 간지럽힘 반응을 강화했다.
- Google 콜백 HTML은 앱에 포함했다. Slack 서버 페이지는 `plead-ops/ddokttihere-server` 커밋 `d756d02`로 배포했으며 공개 콜백의 새 HTML/CSP 응답을 확인했다. 실제 OAuth 재연결은 실행하지 않았다.
- 최종 Rust 55개·Node 44개·서버 11개 검사와 타입 검사, UI/동작 브라우저 검사 통과. Mac 네이티브 통합 검사 60.0Hz/정상 종료, Windows 교차 빌드 통과. 목 옷깃 최종 보정은 이후 SVG 시각 확인과 Rust 전체 검사로 확인했다. Windows VM 실행은 이번 후속 변경 뒤 추가로 수행하지 않았다.
- Windows 설치 정책은 사용자별·WebView2 무인 설치로 명시했다. 기존 CMD/UAC 현상의 실제 재현·완전 해소는 미확인이다. 데스크톱 변경은 공식 릴리스 전이다.

## 이미지 생성 기반 교체

사용자의 명시 요청으로 imagegen 스킬/내장 도구를 사용하여 착지·아야 6컷과 졸기·하품 4컷을 다시 생성했다. 생성 PNG/전체 프롬프트/측정 가이드를 `assets/concepts/generated`에 보관한다. 생성 원화를 기존 팔레트·균등 배율로 VTracer 변환하여 실제 프레임을 교체했고, 수작업 아야 몸통 합성 함수와 하품 녹색 덧칠을 삭제했다. 작은 말풍선, 창 끝 반응, 상단 손 접점·진행 방향·놀이 휴식 시간 수정은 유지한다.
