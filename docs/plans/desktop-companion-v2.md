# 똑띠 데스크톱 동료 개편 계획

산책 정렬 보정: `preview.js`에서 walk-sheet-v3 각 프레임의 실측 불투명 실루엣 상단/발바닥 좌표를 사용한다. 아래 행이 약 20 source px 높고 조금 작게 그려진 차이를 보정하기 위해, 종횡비를 유지한 148px 실루엣 높이와 y=264 발바닥 기준으로 렌더링한다. 들린 발의 포즈와 좌우 이동은 유지한다. PNG를 교체할 때는 해당 등록 좌표도 다시 측정해야 한다.

최신 알림 디자인 연구: **04**, `assets/concepts/ddoktti-v2/notifications.html`. 새로운 알림 키 포즈(`alert-poses-v1.png`) 4종×4장과 일회성 이동/점프/착지 연출, HTML/CSS 말풍선을 결합했다. 8~12장의 독립 프레임 제작이 아니라 4개 키 포즈와 연속 변형으로 동작을 구성한 시안이다. `speech-bubble.js`는 HTML 생성과 action callback만 담당하며, `notifications.js`는 예시 데이터·시간 진행·동작을 담당한다. 실제 앱과 외부 서비스에는 연결하지 않았다. 버튼 동작은 시뮬레이션임을 명시하고, 내용 숨기기·모션 줄이기·좌우 배치·다시 재생을 제공한다. 상세 생성 프롬프트는 `generation-prompts-v4.txt`에 보존한다.

앱 이식 시: 현재 정사각형 overlay 창에는 말풍선이 잘리므로 캐릭터 발 앵커를 유지한 창 확장 또는 별도 말풍선 창이 필요하다. 말풍선 크기 측정 후 작업 영역 안으로 보정하고, 투명 여백의 클릭 통과와 버튼 클릭 영역을 분리한다. 미리보기의 좌우 스위치는 이 배치 검토용이며 실제 다중 모니터 경계 감지 구현을 대신하지 않는다. 알림 텍스트는 textContent로 주입한다. 사용자에게 보이는 제목/본문이 확정된 시점에 접근성 알림을 1회 전달하고, 캐릭터 동작이 창 포커스를 빼앗지 않도록 구현한다.

최신 시안: **03**. `preview.html`은 짧은 다리의 `walk-sheet-v3.png`(8프레임)와 새로 그린 `slack-sheet-v2.png`(4프레임)를 재생한다. 사용자 피드백에 따라 산책의 발 동작은 유지하고 다리 비율을 줄였으며, Slack도 새 그림체와 짧은 다리 비율로 재제작했다. 시안 02의 ‘Slack 원본 재생’은 이 버전에서 대체되었다. 이전 PNG와 실제 앱 원본은 보존한다. 정확한 생성 프롬프트는 `assets/concepts/ddoktti-v2/generation-prompts-v3.txt`에 저장했다.

## 목표와 범위

평소에는 산책하고 쉬는 똑띠가 슬랙, 내 구글 캘린더 일정, 스트레칭, 타이머를 알려준다.
Windows 10/11과 macOS를 공동 대상으로 삼고 Tauri 2 + TypeScript를 유지한다. Slack은 사용자 계정 권한으로 메시지 이벤트를 받는 연동 앱으로 전환한다. Google Calendar도 계정 연결을 통해 사용한다.
기존 시안은 디자인 참고 자료이며, 제품 구현 및 서비스 연결 여부와 구분한다.

## 확정 방향: 계정 연결 안내

사용자는 Slack과 Google Calendar의 계정 연결을 안내하는 방향에 동의했다. 서비스 연결을 앱 전체 사용의 필수 조건으로 만들지는 않는다.

1. 첫 실행에서 ‘항상 함께하기’와 ‘알림이 있을 때만 만나기’를 선택한다.
2. ‘똑띠가 무엇을 알려줄까요?’ 화면에 Slack과 Google Calendar 연결 카드를 나란히 표시한다. 각 카드에 연결 목적과 버튼을 제공하고, ‘나중에 연결하기’로 건너뛸 수 있게 한다.
3. Slack 카드: ‘내 DM과 멘션을 알려드려요’ / ‘Slack 연결’. 연결 뒤 워크스페이스와 사용자 계정을 확인시키고 DM·직접 멘션·전체 멘션·그룹 멘션 설정을 보여준다.
4. Google Calendar 카드: ‘다가오는 내 일정을 알려드려요’ / ‘Google Calendar 연결’. 연결 뒤 알림 시점만 설정한다. 캘린더 자동 탐색과 미응답 초대 기본 포함을 안내한다.
5. 완료 화면에서 선택 내용을 요약하고 캐릭터를 시작한다. 연결하지 않은 서비스의 알림만 비활성화하며 타이머·스트레칭·캐릭터 기능은 사용할 수 있다.

설정의 ‘연결된 계정’에서도 동일한 카드를 제공한다. 상태는 미연결 / 연결 중 / 연결됨 / 일시적인 통신 문제 / 재연결 필요 / 관리자 승인 필요를 구분한다. 일시적인 네트워크 실패를 곧바로 계정 해제로 취급하지 않는다. 인증 취소는 오류 화면 대신 미연결 상태로 돌아간다.

연결 해제는 해당 서비스의 토큰·캐시·대기 알림을 제거하고 다른 서비스와 타이머는 유지한다. 로컬 연결 해제와 제공자 측 앱 권한 철회는 구분해서 안내한다. 토큰은 OS 자격 증명 저장소 또는 인증 서버에서 관리하며 웹뷰·일반 설정 파일·로그에 기록하지 않는다.

### Slack 수신 및 인증 설계

- 내 ID는 계정 연결 결과에서 얻는다. 봇 자신의 ID와 사용자 ID를 구분하고 워크스페이스 ID와 함께 보관한다.
- 사용자 권한의 메시지 이벤트로 DM과 공개 채널 멘션을 판별한다. `app_mention`은 봇 멘션 이벤트이므로 내 멘션 감지에 사용하지 않는다. 그룹 멘션은 그룹 구성원 정보를 조회해 판별한다.
- 비공개 채널은 사용자가 참여하고 접근 권한을 허용한 범위에서만 확장 가능하다. 초기 요청 범위인 공개 채널·DM과 별개로 권한 및 UI를 결정한다.
- Slack 방해금지는 반영하되, 채널별 음소거·키워드·알림 일정 전체가 자동 복제된다고 안내하지 않는다. 앱의 알림 종류 및 제외 대상 설정을 제공한다.
- Windows Slack 알림 리스너와 권한 요청·신원 패키지 설치를 제거한다. Slack은 API 단일 수신 방식이며 연결이 끊기면 상태를 표시한다. OS 알림 방식으로 전환하지 않는다.
- 개인 개발 검증에는 Socket Mode를 사용할 수 있다. 여러 사용자에게 배포하는 제품은 브라우저 OAuth와 인증/이벤트 중계 서버를 설계한다. 공용 앱 토큰이나 client secret을 배포 바이너리에 포함하지 않는다. Socket Mode의 이벤트는 앱 단위이므로 여러 PC 연결을 사용자별 전달로 가정하지 않는다.
- 사용자에게 개발자 토큰 복사·입력을 기본 연결 UX로 요구하지 않는다. 배포용 Slack 앱 등록, redirect URL, 사용자 권한, 워크스페이스 설치 정책을 준비해야 실제 연결 버튼을 활성화할 수 있다. 준비되지 않은 빌드에 가짜 연결 성공을 표시하지 않는다.
- 중계 서버 사용 시 설치 권한과 수신 사용자 범위를 검증하고, 이벤트 ID 중복 방지·토큰 철회·재연결·연결 해제를 처리한다. 메시지 본문은 기본적으로 영속 저장하지 않는다.

근거: [Slack Events API](https://docs.slack.dev/apis/events-api/), [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/), [방해금지 조회](https://docs.slack.dev/reference/methods/dnd.info/).

## 기본 사용자 경험

- 상주 모드: 작은 똑띠가 선택한 화면 아래쪽을 걷고, 멈추고, 졸고, 혼자 논다.
- 알림 도착: 현재 위치에서 멈추고 종류별 동작과 짧은 말풍선을 표시한다. 자동으로 다른 화면으로 순간이동하지 않는다.
- 확인/닫기: 알림만 처리하고 평상시 행동으로 복귀한다.
- 마우스를 올리면 멈춘다. 드래그하면 들림 상태가 되고 놓으면 착지한다.
- 평상시 클릭은 작은 메뉴(타이머 / 오늘 일정 / 잠깐 쉬기 / 설정), 알림 중 클릭은 해당 알림 동작이다.
- 알림 전용 모드도 유지한다. 이 모드에서는 기존 출현 모니터와 위치 설정을 사용한다.
- 우클릭 및 트레이에서 상주/알림 전용 전환과 일시 숨김을 제공한다.
- 기본 산책은 한 모니터의 하단 작업 영역으로 제한한다. 창 위 걷기와 모니터 사이 자유 이동은 후속 범위다.

## 모니터와 설정 정책

두 모드를 명확히 분리한다.

| 항목 | 상주 모드 | 알림 전용 모드 |
|---|---|---|

| 알림 발생 | 현재 화면·현재 위치 유지 | 출현 정책으로 배치 |
| 화면 분리 | 주 화면으로 옮기고 경계 보정. 원래 선호 화면은 기억 | 기존 주 화면 폴백 유지 |
| 화면 재연결 | 즉시 이동하지 않고 다음 시작 또는 사용자의 ‘이 화면으로 이동’에서 복귀 | 다음 알림에서 기존 지정 화면 사용 |

- 저장 설정과 런타임 위치는 구분한다. 산책 프레임마다 파일을 쓰지 않는다.
- 기존 사용자에게는 알림 전용 모드를 유지하고 ‘똑띠와 함께하기’로 상주 모드를 안내한다. 신규 설치는 상주 모드 기본을 제안한다.
- `display.json`을 보존하고 버전 있는 설정으로 1회 마이그레이션한다. 알림 전용 위치·배율을 상주 설정으로 덮어쓰지 않는다.
- 모션 줄이기, 항상 위, 음량은 명확한 공통 옵션. 산책 속도와 알림 애니메이션 속도는 구분한다.
- 창 크기를 바꿀 때 캐릭터의 발 위치를 기준으로 정렬하고 말풍선은 화면 안쪽 방향으로 배치한다.

## 구글 캘린더: 내가 포함된 일정

### 첫 버전의 명시적 범위

- Google 계정 1개의 캘린더 목록을 매 동기화마다 자동 조회한다. 공유·보조·숨김 캘린더도 읽기 권한이 있으면 포함하며 수동 선택은 제공하지 않는다.
- 내가 주최한 일정과 내 참석 상태가 accepted/tentative/needsAction인 초대를 포함한다.
- 미응답 초대는 기본 포함이며 별도 스위치를 제공하지 않는다. declined, cancelled는 제외한다.
- 기본 캘린더의 참석자 없는 개인 일정과 다른 캘린더에서 내가 만든 개인 일정을 포함한다. 공유 캘린더의 단순 소유/관리 권한만으로 남의 개인 일정을 포함하지 않는다. 종일 일정, 생일, 근무 위치, 부재중 같은 항목은 기본 제외한다.
- 반복 일정은 각각의 occurrence로 확장하고 시간 변경·취소·예외 날짜를 반영한다.
- 기본 알림은 시작 5분 전 1회. 1/5/10/15분 전으로 변경 가능.
- ‘일정 열기’, 지원되는 화상회의 링크가 있을 때 ‘회의 참여’, ‘1분 후 다시’ 제공. 시작 후에는 다시 알림 대신 일정 열기만 제공한다.
- 제목 표시를 끄는 옵션을 둔다. 켜진 경우 ‘곧 일정이 시작돼요’로 표시한다.

### 인증과 동기화 설계

- 시스템 브라우저 + Desktop OAuth client + PKCE(S256) + 일회성 state + loopback callback을 사용한다. callback은 localhost에만 바인드하고 성공/취소/시간 초과 후 종료한다.
- 첫 연결에서 `calendar.events.readonly`와 `calendar.calendarlist.readonly` 권한을 요청한다. 미배포 상태이므로 이전 버전 사용자용 권한 변경 안내는 제공하지 않는다.
- `attendees[].self`는 해당 이벤트 사본의 캘린더 기준이다. 로그인 계정의 기본 캘린더 ID(이메일)와 주최자·작성자·참석자 이메일을 비교하며 self 표시는 primary에서만 사용자 판별에 쓴다.
- refresh token은 Windows 자격 증명 저장소 등 OS 보호 저장소에 보관. access token은 Rust 메모리. 연결 해제 시 토큰·예약 알림·캐시를 정리한다.
- 최근/다가올 제한된 시간 범위(예: 현재~7일)를 `events.list(singleEvents=true)`로 초기 조회하고 약 60초마다 재조회한다. 페이지네이션·429/5xx 백오프·401 재인증·수동 새로고침을 처리한다.
- 수신한 UTC 시각으로 로컬 알림을 예약한다. API 폴링 시점에만 울리는 방식은 피한다. 시간대와 DST를 고려한다.
- 알림 dedup은 계정 + iCalUID + 반복 일정 originalStartTime(UTC 정규화) 기준. 비반복 일정은 iCalUID 기준이다. 같은 회차의 이동은 동일한 키를 유지하며 대기 알림 정보를 갱신한다. 취소/삭제/제외 상태 변경 시 대기·표시 알림을 회수한다.
- 절전 복귀 시 먼저 재동기화. 이미 종료된 일정은 버리고, 현재 진행 중인 일정은 시작 후 5분 이내인 경우에만 1회 안내한다.
- 네트워크 실패 시 마지막 동기화 시점을 보여주고 기존 메모리 캐시 기반 예약만 유지한다. 앱 재시작 후 오프라인이면 일정 정보를 새로 가져올 수 없음을 표시한다.
- 알림 중복 방지 이력은 제목/본문 없이 최소 키와 만료 시각만 보관한다.
- 배포 준비 항목: Google Cloud 프로젝트, Calendar API 활성화, Desktop client ID, 동의 화면 및 대상 사용자 설정, 배포 범위에 따른 검증 요건 확인. 구현용 mock과 실제 계정 연결 검증을 분리한다.

근거: [Google native OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), [event 필드](https://developers.google.com/workspace/calendar/api/v3/reference/events).

## 스트레칭 권유

- 실제 착석을 측정하지 않는다. ‘PC 사용이 이어지면 알려주기’로 설명한다.
- 기본 50분, 30/50/60/90분 설정. 입력 없는 시간이 5분 이상이면 휴식으로 간주해 누적을 리셋한다.
- Windows `GetLastInputInfo`로 입력 유휴 시간을 샘플링한다. 잠금/절전은 누적을 중단하고 복귀 시 오래된 권유를 버린다.
- 영상 시청 등 입력 없는 활동은 사용 시간을 과소 추정할 수 있다. ‘직접 휴식 시작’도 제공한다.
- 똑띠가 기지개를 켜고 ‘잠깐 몸을 풀까요?’ 표시. ‘쉬었어요’, ‘10분 뒤’, ‘오늘은 끄기’ 제공.
- 무응답이면 짧은 표시 후 돌아가고 자동 반복 재촉하지 않는다. 다음 주기는 그 안내 시점부터 다시 계산한다.
- 캘린더상 진행 중인 참석 일정에는 권유를 보류하고 일정이 끝난 뒤 활성 사용이 이어질 때 최대 1건 안내한다. 이것은 실제 회의 참가 감지가 아니다.

근거: [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo).

## 타이머

- 초기 범위는 동시 실행 1개. 5/10/25/50분 프리셋과 직접 입력(1분~24시간).
- 이름, 시작, 일시정지, 재개, 취소, 같은 시간 다시 시작 지원.
- 실행 중에는 메뉴에 남은 시간 표시. 종료 시 시계 소품과 짧은 완료 동작, 확인 전까지 작은 완료 표시 유지.
- Rust가 실행 상태와 마감 시각을 소유한다. 웹뷰 interval은 표시용이며 설정창이 닫혀도 진행된다.
- 실행 중에는 단조 시계로 남은 시간을 계산하고 복구용 UTC deadline도 저장한다. 절전 시간은 타이머 경과에 포함한다. 실행 중 시스템 시간 변경은 남은 시간을 보존하도록 deadline을 재조정한다.
- 재시작 시 저장된 deadline으로 복원한다. 종료된 타이머는 1회 완료 상태로 복원하고 오래된 완료음은 반복하지 않는다. 앱 종료 중의 시계 변경은 완벽히 구분할 수 없음을 구현 문서에 명시한다.
- 완료/확인 상태를 영속 저장해 재시작마다 다시 울리지 않도록 한다.

## 알림과 캐릭터 상태 분리

- Pet state: idle / walk / look / sleep / dragged / edge-wobble / recover / fall / land / notify / stretch / celebrate.
- Alert: kind(slack/calendar/stretch/timer), id, priority, createdAt, expiresAt, actions, acknowledgement, snoozeUntil.
- 행동 상태는 알림 내용을 보관하지 않는다. Rust AlertHub가 실제 알림 큐와 타이머를 소유하고 TS는 snapshot+event로 렌더링한다.
- 오버레이 재로딩 시 snapshot으로 복원하고 중복 이벤트는 ID로 무시한다. JS 리스너 준비 전 알림 유실을 막는다.
- 타이머 완료·일정 임박을 높은 우선순위, Slack을 일반, 스트레칭을 낮은 우선순위로 처리. 같은 우선순위는 오래된 항목부터 표시한다.
- 긴급 알림은 드래그 종료 후 표시하고 평상시 행동은 즉시 중단 가능하다. 애니메이션 완료와 알림 확인은 별개다.
- 한 번에 말풍선 1개. 동일 일정·동일 타이머는 중복 병합, Slack은 기존 ID별 해제 유지. 밀린 스트레칭은 1개로 합친다.
- 알림 확인과 발생원 상태를 분리한다. 똑띠에서 닫기는 Google 참석 응답이나 Slack 읽음 상태를 변경하지 않는다.
- 캐릭터 숨김은 알림 확인이 아니다. 알림 일시 중지와 시각적 숨김을 구분하고 타이머 진행 여부를 메뉴에 보여준다.
- 전체 화면에서는 산책을 멈추고 작은 알림만 표시하는 것을 기본 제안한다. 사용자가 알림까지 끄면 무음으로 완료/수신 상태만 유지한다.

## 완료 기준

- 화면 A에 사는 똑띠가 커서가 B에 있다는 이유로 알림 때 이동하지 않는다.
- 소리/속도 변경은 위치를 바꾸지 않는다. 명시적인 모니터 변경만 이동시킨다.
- B로 드래그한 뒤 알림 수신·앱 재시작 후에도 B 설정이 유지된다.
- 자동 산책 중 설정 파일을 반복 기록하지 않는다. 드래그와 자동 이동이 동시에 실행되지 않는다.
- 모니터 제거, 음수 화면 좌표, 100/150/200% 혼합 DPI, 작업표시줄 위치 변경에서 캐릭터/말풍선이 화면 밖에 남지 않는다.
- 미리보기 닫기가 실제 알림을 지우지 않는다. Slack 확인이 일정/타이머를 지우지 않는다.
- 투명 여백은 배후 앱 클릭을 가로채지 않는다. 캐릭터/말풍선 조작은 정상 동작한다.
- 모션 줄이기 상태에서 산책/점프가 없고 알림은 읽을 수 있다.
- 반복 일정의 변경·취소, declined, 미응답 기본 포함, 종일 일정, DST, 페이지네이션, 재인증, 오프라인/복귀를 테스트한다.
- 타이머 pause/resume/절전/재시작/시계 변경과 스트레칭 유휴·잠금·회의 보류를 가짜 시계 단위 테스트로 검증한다.
- Windows 실행에서 CPU/메모리와 idle 상태를 측정하고 상주에 따른 지속적인 높은 부하가 없는지 확인한다. 이번 조사에서는 미측정이다.

## 시안 02: 사용자 피드백 반영

이 절이 위 시안 01 설명보다 우선한다. 실제 앱 구현 전 애니메이션 연구 단계는 유지한다.

1. **Slack 누락 수정**: 제품 기능은 삭제된 적 없지만 시안에 빠져 있었다. 미리보기 첫 카드에 기존 `assets/sprite1.png`~`sprite5.png` 원본을 400ms 간격으로 재생한다.
2. **일정 하단 점**: 기존 4×4 시트에서 타이머 행의 세 번째 안테나가 일정 행의 아래쪽 영역까지 침범하는 것이 보인다. 분수 셀 크기뿐 아니라 그림 자체의 행 경계 침범 문제다. 일정은 독립 4프레임 시트 `calendar-sheet-v2.png`로 다시 생성하고 명시적 source rectangle로 표시한다.
3. **산책 재제작**: 기존 비슷한 포즈 반복 대신 접지·다리 들기·통과·내딛기 포즈를 요청한 `walk-sheet-v2.png` 생성. 8프레임과 왕복 이동을 연결했다. 두 반주기의 자세 유사성과 프레임별 정렬은 최종 제작 시 더 정제할 대상이다. 생성 프롬프트의 요구사항이 모두 충족됐다는 의미는 아니다.
4. **가장자리/낙하 추가**: `edge-sheet-v1.png` 상단은 균형 잃기→버티기→회복→안도, 하단은 낙하→발 내밀기→웅크린 착지→일어서기. 미리보기는 낙하에 가속 이동을 적용하고 착지는 한 번만 재생한 뒤 안정 자세를 유지한다. 데모 반복 때만 시작 위치로 돌아간다.

참고 방식: VS Code Pets의 `WallHangLeftState`, `JumpDownLeftState`, `LandState`처럼 행동과 위치 갱신을 분리한다. eSheep의 작업표시줄까지 떨어지는 동작도 참고했다. 두 프로젝트의 캐릭터 아트를 복제하지 않고 똑띠 새 포즈를 생성했다.

### 제품에서의 발생 조건

- 드래그하여 바닥보다 높은 곳에 놓으면 `fall → land → idle`. 물리 위치를 실제 작업 영역 바닥으로 clamp한다. 모션 줄이기에서는 즉시 안전 위치로 이동하고 정지 포즈를 표시한다.
- 화면 아래의 산책 경계에서는 드물게 `edge-wobble → recover → walk`. 화면 밖으로 실제 낙하하지 않는다. 화면 가장자리는 실제 높은 발판이 아니므로 안전한 연출로만 취급한다.
- 다른 프로그램 창 위에서 떨어지는 행동은 창 경계 감지를 구현한 후 추가한다. 시안의 발판은 동작 설명용이며 현재 앱에 창 감지 기능이 생긴 것은 아니다.
- 흔들림 중 중요 알림이 오면 회복 후 알림 상태로 전환. 낙하 중에는 정상 착지 후 알림을 보여주고, 드래그 중에는 놓을 때까지 대기한다. 물리 처리와 알림 표시가 서로 위치를 덮어쓰지 않는다.
- 걷는 동안 현재 발 접지 위치와 이동 속도를 맞춰 미끄러짐을 줄인다. 방향 전환은 가장자리 정지 후 수행하고 발 동작만 역순 재생하지 않는다.
- 낙하 위치를 매 프레임 사용자 지정 위치로 저장하지 않는다. 상시 노출은 착지 위치를 설정에 저장하지 않는다. 알림 전용 모드만 드래그 종료 시 놓은 자리를 저장한다.

### 창 위 자율 이동 구현 (2026-09-30)

- 150ms 간격으로 창 목록을 갱신하고 모니터 작업 영역 기준 논리 좌표로 변환한다. Win32 물리 픽셀과 CoreGraphics 논리 포인트의 변환을 구분한다. 창 목록 조회 실패 시 바닥 이동으로 돌아간다.
- 위쪽 창에 가려지는 윗면과 캐릭터 머리 공간을 잘라낸다. 몸 너비를 지탱할 만큼 충분한 발판에만 착지한다. 자체 물리 시뮬레이션은 최대 1/60초 하위 스텝으로 계산해 빠른 낙하 때 발판을 통과하지 않도록 한다.
- 창 ID와 상대 위치를 유지하므로 창 이동·크기 변경을 따라간다. 닫힘·최소화·가림·모니터 이탈로 발판이 없어지면 낙하한다.
- 상태: 지면/발판 → 붙잡기 → 등반 → 몸 끌어올리기 → 착지. 가까운 발판으로는 준비 → 포물선 점프 → 착지한다. 가장자리에서는 휘청인 뒤 주로 방향을 돌리고, 가끔 미끄러져 아래 발판으로 내려간다.
- 도달 가능한 높이/거리, 몸 전체의 화면 안 공간을 만족하는 창만 목표로 삼는다. 캐릭터는 현재 모니터 안에서 활동하며 드래그로 모니터를 옮기면 해당 모니터 기준으로 다시 감지한다.
- 알림·메뉴·마우스 호버 중에는 새로운 이동을 시작하지 않는다. 진행 중인 점프/등반은 안전하게 완료한 다음 알림·예약된 메뉴/간지럼을 표시한다. 전체 화면 숨김 중 물리 갱신을 멈추며, 동작 줄이기에서는 발판 손실을 정지 위치로 바로 해결한다.
- `surfaces-v2.png`에 등반·끌어올리기·이동 점프·매달리기 16프레임을 추가했다. 생성 프롬프트와 도구는 `assets/concepts/window-motion-prompts.json`에 보관했다. 기존 달리기 에셋은 유지한다.
- `/surfaces.html`은 동일 엔진으로 만든 가상 창 체험 페이지다. 창/캐릭터 드래그, 창 크기 변경, 닫기·다시 열기, 알림 도착과 동작 줄이기를 확인할 수 있다. 실제 앱에 동작 선택 메뉴는 추가하지 않았다. `/motions.html`에도 신규 동작 5종을 추가했다.
- 첫 시작 화면은 기존 `sprite3.png` 대신 인사 스프라이트의 웃으며 손 흔드는 그림을 사용한다.
